# 首页后台预加载复核 · 2026-10-26

## 需求与实现

用户要求：打开首页后后台准备其他页面，大图正常加载，视频按需加载；延续上一轮导航和滚动不能等待媒体加载的修复。

- 首页渲染后约 2.4 秒开始利用空闲时间排队预取，每 900 毫秒安排一个页面，不等待 `window.load`。
- 预取当前语言的 16 个公开页面：产品总览、品牌故事、方案、FAQ、候补、5 个产品页、关于、联系、4 个法律页面。
- 使用 Next 的完整路由预取，将动态页面内容放入已有路由缓存，不挂载其他页面及其媒体组件。
- 提前加载 7 张主要大图/视频封面，匹配实际页面的响应式图片地址，最多 2 张同时请求，低优先级。单张超时会释放队列。
- 不下载其他页面的视频；当前页面原有的开场动效、接近视口或用户播放时的媒体逻辑保持原样。
- 后台会员、订单、结账、登录、API 和草稿不在预取清单内。内容预览模式不启动预取。
- 省流量模式、2G、离线和隐藏标签页暂停安排后台请求；离开首页清理尚未安排的任务和在途图片。
- 无布局、品牌文案、背景、后台业务、数据库与账号配置变更。

第二轮覆盖：大图跳转时复用完全相同的响应式缓存地址；慢后台页面请求不阻塞点击导航；开场视频一直等待时菜单、导航、滚动和主按钮仍可使用；脚本尚未到达时页面可滚动；2560×640 和 3840×960 的 16:4 布局；开场与流动背景随正反向滚动变化。保留原断言，未通过跳过测试或替换截图基准使结果通过。

首轮单元测试出现 2 项环境失败：独立副本缺少原有后台字段清单 JSON，错误为 ENOENT。将项目中已有的 3 个内容配置 JSON 原样复制到隔离副本后，198 项全部通过；未改变应用或测试断言。首次失败日志保留在 `unit.log`。
