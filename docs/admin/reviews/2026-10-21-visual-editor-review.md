## Initial confirmed findings (all fixed)

1. **[P1] Keep programmatic language navigation inside the read-only canvas.** `related/website/components/content/visual/VisualCanvas.tsx:60-70` only intercepts anchor navigation while allowing all browse-mode buttons. `SiteHeader.tsx:122-130` implements the language picker with `router.replace`, using `useSitePathname()` (the selected public page). Selecting Japanese while previewing Products therefore navigates from `/en/preview/<draft>?page=/products&editor=...` to `/ja/products?page=/products&editor=...`. The public route unmounts `VisualCanvas`, discards the in-memory snapshot, and removes the preview's form/fetch guards; subsequent interactions run the ordinary website. Route this operation through the parent preview locale control or prevent the picker operation inside visual previews.

2. **[P1] Intercept clicks originating on SVG elements.** `related/website/components/content/visual/VisualCanvas.tsx:52` returns unless the event target is an `HTMLElement`; Lucide `<svg>` and `<path>` nodes are `SVGElement`s. `MembersArea.tsx:46,66` contains link arrow icons, so clicking the arrow bypasses preview navigation interception and follows `/faq` or `/products` as a public route. The cart/menu SVG icons also execute their handlers in edit mode. This provides a second ordinary pointer path that leaves the read-only canvas and its guards. Normalize an `Element` target to its relevant HTML ancestor before applying edit or browse interception.

3. **[P2] Preserve fragments when following cross-page links.** `related/website/components/content/visual/VisualCanvas.tsx:67` sends `{page, hash}`, but `related/admin/features/content/VisualPreview.tsx:26` forwards only `message.page`, and its iframe URL contains no destination fragment. The existing homepage link `/story#brand-film` therefore opens the top of Story, rather than its video section. Carry a validated fragment through parent navigation and scroll after the destination renderer has mounted.

The implementing agent was notified of all three findings while review was in progress.

## Checked boundaries and withdrawn concern

- Existing save/submit/publish endpoints, optimistic version request fields, conflict-copy handling, and role filtering remain in place; the reviewed changes introduce no migration or new business API.
- Server preview loading still uses the existing live staff check and draft RPC access; invalid editor channels and missing/invalid configured admin origin fail closed.
- Parent/frame messages check configured exact origin, source window, UUID channel, and recognized message kind. Unsaved snapshots travel only in postMessage data and React state.
- The canvas's cart provider skips persisted-cart restore, storage events, and localStorage writes; the ordinary public provider keeps its previous behavior.
- Candidate matching retains all exact duplicate matches, filters locale/page/global scopes, excludes background/video slots, and sends a candidate list rather than guessing.
- Current `ContentEditor` keys `VisualPreview` by selected page and locale. That remount resolves the initially suspected failure to resend an unchanged snapshot after iframe page/locale navigation; it is **not** an outstanding finding.
- The generated private renderers are checked against source by the prebuild script. Print is now included with Home, Story, and Contact, and the private renderer map imports generated Print.

## Performance observation (not a finding)

The actual manifest has 3,696 editable fields and 666 fields relevant to the English homepage. A read-only Node probe measured about 1.6 ms per `canvasCandidates` search on this machine. The latest hover handler caches the DOM target and snapshot, avoiding repeated candidate searches while moving within the same unchanged target. Browser responsiveness should still be observed during interaction testing; this source-only review does not claim a measured hover performance regression.
