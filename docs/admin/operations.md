# 本地使用与运维

本地预览由本机进程和本地 Docker 服务提供；关机或停止进程后需要重新启动，不代表永久在线托管。账号只用于本地测试，不能带入生产。

- 官网：<http://127.0.0.1:4211/en>（另有 `/zh-hant`、`/ja`）。
- 后台：<http://127.0.0.1:4270/login>。
- 本地私有凭据：仓库 `.lumiq-local/preview-credentials.json`，权限0600；其中列出管理员、编辑、运营账号。该目录被 Git 忽略，禁止上传或放入公共资源。
- 本地邮件：Mailpit <http://127.0.0.1:54324>。官网注册/重置使用已加入本地 Auth 白名单的4211 callback；在邮箱中打开真实本地确认链接。

从仓库根运行：

```sh
# 本机已有独立 Node 22 时，可将它加入 PATH（此路径不属于项目必需依赖）
export PATH="$PWD/.lumiq-local/node22/node_modules/node/bin:/opt/homebrew/bin:$PATH"
export DOCKER_HOST=unix:///Users/huangshaotai/.colima/lumiq-platform/docker.sock
supabase start
node scripts/local-preview.mjs start
node scripts/local-preview.mjs status
node scripts/local-preview.mjs restart
node scripts/local-preview.mjs stop
```

本地入口4211/4270由任务自己的 loopback 代理提供，覆盖客户端的转发身份头并从 socket 取得 x-real-ip，内部 Next 使用4212/4271；这让真实浏览器登录/写入满足既有可信入口约束，不是生产代理验收。

私有 `.lumiq-local/preview-config.json` 持久化两站的 `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`、服务端 `SUPABASE_SERVICE_ROLE_KEY`，以及官网报名存储必需的 `SUPABASE_URL`。本机两个 URL 必须明确为同一已验证的 `http://127.0.0.1:54321`；启动器拒绝缺失或不匹配的保存值，不会从调用 shell 补入其他项目端点。其余运行变量包括 `REQUEST_LIMIT_SALT`、`REQUEST_IP_HEADER`、媒体路径/限额和邀请 SMTP 配置，详见 [deployment.md](deployment.md)。

stop 只停止启动器验证过的本任务进程组，不操作原4240/4241/4242预览。端口被其他程序占用会报错，不自动杀进程。运行目录 `.lumiq-local/preview/related/{website,admin}` 拥有独立已安装依赖、生产构建和素材；其生命周期不依赖临时 SDD 文件。配置、日志与测试历史备份均在 `.lumiq-local/`，不要将其公开。

`setup --reset-synthetic-local` 是破坏性的合成环境初始化，不是重启命令。本次交付只在核实本任务 loopback、容器 project 标签、无非测试账号并先保存原合成历史后执行。存在交付配置后 setup 会拒绝再次运行，即使带显式 reset 参数也不能覆盖用户后续编辑。源代码更新后必须在隔离环境重新验证并按部署流程更新构建，不能只修改运行目录掩盖源码。

## 功能操作

管理员可邀请/停用员工、分配角色，管理公开内容及素材，处理会员/候补和订单并查看权限范围内审计。编辑管理普通内容草稿和素材；敏感商业内容、发布及管理员操作保持受限。运营处理会员、候补及订单，不可读取草稿或配置商业/隐私策略。直接 API/SQL 请求也按当前数据库权限校验。

官网使用三语真实注册、确认邮件、登录/退出、资料和收件地址、密码重置、订单读取/取消；设备区域明确显示尚未连接。购物车展示参考价，实际待付款订单由数据库确认价格与批准条款生成，重试保持幂等；当前初始下单关闭。订单内部备注不会出现在会员响应。

内容编辑流程：新建草稿 → 修改 → 保存 → 在官网独立登录员工账号后预览 → 受权发布。已发布读取缓存最长60秒；草稿/账号/订单不缓存。官网独立读取数据库已发布快照，后台进程停机不影响官网读取；数据库失败保持最近成功的内容或内置初始快照，绝不以空结果覆盖成功内容。字段历史与当前编辑范围有所区别：4396原始字段、111素材槽、278历史定位记录；实际适配 guard 为156处代码/CSS消费和61个顺序媒体 alt 绑定，不能解释为278个独立行为断言。退役的旧会员演示字段有明确台账。

错误处理：保存/邮件/上传失败会显示错误；输入在待保存期间锁定，失败保留文本。冲突需刷新后重试；不能将不确定网络响应当作成功。媒体孤儿不可公开访问，发布失败保留旧指针。恢复匿名化任务前核对保留策略与失败步骤，访问暂停一直保持到受控流程完成。

## 重复验收与数据边界

统一命令：`node scripts/verify-platform.mjs`。它只允许本地固定项目，默认从 CLI 安全取得合成凭据，并在独立镜像中 `npm ci` 和执行原生 build。先跑SQL，再顺序跑浏览器；不要同时在同一数据库启动人口/并发 SQL 和浏览器账号 fixture。

交付预览已初始化后，统一测试、SQL/浏览器阶段和故障反例会拒绝运行；即使预览已停止也不会解除保护。已有 Auth/profile/报名/订单/备注、非初始发布快照或未恢复的 fixture 备份也会触发拒绝。验证不会自行 reset，不删除后续用户内容。

重新完整验证需要**新的可丢弃 checkout 和独立 Docker 环境**，其中不得连接交付预览的数据卷/容器；仅复制一份源码不能隔离现有 Docker 数据。CI 每次创建独立临时数据库，完成后 `supabase stop --no-backup` 清理。选定的纯 `--stage=contracts`、`checks`、`build` 可以在不操作数据库 fixture 的情况下运行。

验证器的原子运行锁防止另一条验证命令刷新正在执行的测试镜像。SIGTERM/SIGINT 会先停止并回收本次阶段及其后代，等待正在进行的准备操作结束，再释放带所有权 token 的锁；重复信号不会释放后继运行的锁。SIGKILL 或无法证明清理完成会保留锁。阶段主进程退出后仍保留其进程组所有权；阶段完成时同样检查残留，不能直接开始下一个阶段。对基线之后出现、无法归属的新同用户进程，只记录不确定性，绝不自动终止；保留锁及 `teardown.json`（PID/父PID/进程组/启动身份，不含命令参数），退出失败。已有无关进程不受影响。这是保守的本机POSIX检查，不是通用进程沙箱：其他本机工作同时启动进程也可能引发误拒绝，应使用安静的可丢弃环境；root进程测试逐文件串行运行。若需要更强保证，应使用独立进程/容器边界。若锁仍存在，先核对 `.lumiq-local/verification.lock/owner.json` 和对应阶段后代均已退出，再手动清理该锁。`--stage=browsers --browser-from=某个owner` 仅用于明确记录的受影响后续阶段，不表示此前阶段自动通过。


### 最终修复的运维行为

运营角色可从“产品与方案”读取全部实际 SKU（包括未确认和停用项）、币种最小单位价格、条款版本及全局订单开关；页面只读。编辑、会员和匿名用户没有该私有工作区权限。工作台“内容草稿”包含编辑中和已提交审核的工作草稿。

官网已配置内容存储发生加载、缺少发布版本或快照校验失败时，服务器输出 `[lumiq-content-fallback]`，包含固定原因类别、回退来源和经过格式校验的发布 UUID；每个读取器每分钟最多一条，不输出异常原文、快照或个人资料。继续服务最近有效版本或内置快照。未配置的本地构建不报警。

资料和已登录改密接口必须提交 `expectedUserId`，只能限制当前经 Auth 验证的账户。跨标签页切换后旧表单会隐藏并重新读取身份；重新显示前不能提交。公开的邮件重置申请仍使用 POST，不需要账户绑定。
