# 官网内容发布

2026-10-21 增加真实网页点选与未保存内容实时预览；背景和视频分开管理，完整字段与原发布流程保留。使用方式、配置、验证范围与限制见 [可视化编辑说明](visual-editor-2026-10-21.md)。

`/content` 是管理员和内容编辑共享的版本化工作区；运营不能读取草稿。首次没有数据库发布快照时，仅管理员可从仓库导入的现有官网基线创建草稿。基线只用于新建草稿，不会自动发布。后续新草稿从当前已发布快照复制。

正文按安全文本及原有受限 ICU 标签编辑。中文字段名、页面范围、字段分组、语言及分页覆盖完整可编辑清单；搜索支持当前文案、中文字段名和诊断路径。未知语义的字段以当前文字摘录辨认，路径只作次要诊断信息；系统设置仅管理员可编辑。`settings.siteUrl/supportEmail/contactText` 是唯一公开设置来源；它们不会改变 Auth 来源、重定向或素材授权。编辑账号保存完整快照时，服务器和数据库均要求 settings 与当前草稿（新草稿则与当前已发布快照）一致。

保存采用预期版本号。冲突时不会覆盖当前输入，可下载包含原输入的 JSON 副本，再主动载入最新草稿并合并。提交审核与重新编辑都会产生新草稿版本。发布不会修改商业订单或商品收费信息；产品参考价仅用于官网展示。

发布与回滚只允许管理员。发布以全站独立事务锁串行化，生成不可变 release，再同时更新唯一指针和追加审计。回滚复制旧快照并生成新的 release，保留全部旧记录。任何审计失败都会回滚整个操作。草稿接口与管理界面 no-store；官网读取接口 `get_published_content()` 只返回当前 releaseId 与完整快照，匿名不能读取草稿或历史快照。官网适配层应将缓存限制为最多 60 秒。

## 完整校验与数据库边界

完整三语/ICU 校验使用 B1 的官方 FormatJS 解析器，运行在服务器。保存始终写入校验器返回的 normalized snapshot。数据库不尝试用正则模拟 ICU。

1. 服务器用当前用户会话验证有效管理员，并按用户执行写入限流。
2. 服务器读取指定版本的草稿（回滚时读取不可变 release），完整校验并取得 normalized snapshot。
3. 隔离的服务凭证仅调用 `attest_content_snapshot(purpose,id,expected_version,normalized_snapshot,policy_version,actor_id)`。没有该 RPC 的浏览器端入口。
4. 此窄 RPC 重新读取锁定对象，要求 normalized JSONB 与存储快照完全相等，不静默改写。数据库计算 SHA-256，校验有效管理员和 DB 固定策略，生成五分钟凭据，绑定用途、对象、版本、操作者、摘要及策略版本。service_role 没有内容表通用写权限，也不能调用发布或回滚。
5. 当前用户调用 `publish_content_draft` 或 `rollback_content_release`。DB 在锁后检查有效管理员、版本和精确匹配的未过期凭据，原子消费凭据、创建 release、更新指针并记录审计。

直接调用保存 RPC 得到的非法内容不能发布。旧别名与 canonical settings 不一致时，完整校验会产生不同的 normalized snapshot，DB 拒绝签发凭据；必须先通过正常保存生成新的规范化版本。保存/提交新版本会废止旧凭据。过期、错误用途/对象/版本/操作者/摘要/策略及重放都失败关闭。

当前策略 `b1-v1-22cec87` 固定于迁移和服务器 `validation-attestation.ts`，浏览器无法修改。今后改变内容规则、ICU 规则或受信素材策略时，需通过受审迁移同步提升 `private.content_validation_policy.active_version` 和服务器常量，自动使旧凭据失效。不得通过快照设置或浏览器传值选择策略。

B3 现已在精确版本校验后、凭据签发前准备私有不可变素材，在发布/回滚最终 SQL 中校验用途与发布引用。原件、发布副本都保持私有；失败复制不能改变当前指针或公开孤立对象。归档和可信草稿基线、运行前提与格式限制详见 [私有素材说明](media.md)。
