# LumiQ 支付接通准备清单

核实日期：2026-10-20（亚洲/上海）

适用范围：台湾注册的收款主体，销售市场包含欧美、日本、韩国和台湾。用户已确定本次先建设管理后台、真实会员及订单管理，支付预留接口，暂不接通真实收款。

## 一、本次建设与后续开通的边界

- 本次设计包含：会员、订单持久化、订单金额与币种、支付尝试记录、支付渠道适配接口和支付通知处理的扩展位置。
- 在渠道未配置、审核未通过时，明确显示支付尚未开放。没有通过支付平台核实的收款结果，不将订单标记为已付款或触发发货。
- 实际的渠道 SDK/API、通知签名规则、退款及对账，需要在选定服务商和产品后按该渠道正式规范接通并验收；预留接口不等于已经可收款。

## 二、可评估的渠道

| 渠道 | 当前核实情况 | 需要另外确认 |
| --- | --- | --- |
| PayPal 商业账户 | 台湾官网提供商业账户申请说明及跨境商户费用页面，可作为跨境收款候选。[开户说明](https://www.paypal.com/tw/business/open-business-account?locale.x=zh_TW)、[台湾商户费率](https://www.paypal.com/tw/business/paypal-business-fees?locale.x=zh_TW) | 商户能否开通所需结账产品、可收币种、提款方式、银行卡直接支付能力和针对各销售市场的可用性，均以该商户账户获批功能为准。不能把“可接受跨境付款”理解成覆盖所有当地钱包或支付方式。 |
| 绿界 ECPay | 官方列有国外信用卡和银联卡的新台币收款；海外信用卡能力需额外申请/联系销售顾问。[支付服务](https://www.ecpay.com.tw/Business/payment_standard)、[收款方式说明](https://support.ecpay.com.tw/25132/) | 海外卡审核、收款额度、结算、退款、使用的金流产品及本次网站是否满足审核条件。 |
| Stripe | 截至核实日期，公开商户支持地区列表未列台湾，不作为仅有台湾主体时的默认收款方案。[支持地区](https://stripe.com/global) | 如品牌另有其他主体或平台提供特定合作方案，需要以对应主体和正式开通资格重新核实。 |

以上是候选评估，不代表已经替品牌申请或取得收款资格；本次不会开户或建立真实付款。

## 三、品牌方准备的开户资料

### 台湾公司主体

- [ ] 公司中英文法定名称、统一编号、注册地址、联系电话及业务联系人。
- [ ] 完整的公司/商业登记证明。
- [ ] 负责人身份证明；若服务商要求，再提交受益所有人及股权证明。
- [ ] 收款账户的银行名称、户名、账号和账户证明；外币结算或提现资料按所选渠道补充。
- [ ] 商户登录邮箱，以及用于接收平台审核和争议通知的联系人邮箱。

PayPal 台湾开户说明列有法定姓名、商业登记资料、业务说明及商业银行账户信息；身份文件按账户审核要求提交。[PayPal 开户资料](https://www.paypal.com/tw/business/open-business-account?locale.x=zh_TW)、[PayPal 身份核实](https://www.paypal.com/tw/cshelp/article/%E5%A6%82%E4%BD%95%E7%A2%BA%E8%AA%8D%E6%88%91%E7%9A%84%E8%BA%AB%E5%88%86%EF%BC%9F-cip-help606?locale.x=zh_TW)

选择绿界时，还应按其实际申请清单准备公司名下台币账户、经营场所/商品证明及要求的补充材料。绿界公布的审核条件包含中文销售页面与新台币计价。[绿界准备资料](https://support.ecpay.com.tw/4862/)

证件与银行材料由品牌方直接提交到支付平台。公开 GitHub 仓库只保存准备事项，不保存上述材料、账户密码或密钥。

## 四、品牌方确认的网站与经营资料

这是为了完成网站配置和渠道审核而整理的工作清单，不是对所有销售地区法律要求的完整判断。具体条款和税务规则由品牌方及其顾问确认。

| 需要确认的事项 | 用途 |
| --- | --- |
| 正式 HTTPS 域名、网站名称、客服邮箱、公司联系方式 | 商户审核、支付回跳与用户联系。`127.0.0.1` 本地地址不能用作正式支付通知地址。 |
| 首批实际售卖的产品/SKU、库存或预售属性 | 决定哪些商品可创建可支付订单。官网现有参考价格、概念参数和“随主机提供”配件需要正式确认。 |
| 商品实际售价、计价币种、优惠规则、数量限制 | 服务器端计算订单金额；展示价格与实际扣款金额应清晰一致。 |
| 分地区运费、可配送国家、发货地、交付时间 | 结账前计算总价并给出交付信息。 |
| 税费/关税承担方式、发票需求 | 作为订单字段和结账说明的配置依据，不自动假定各市场规则相同。 |
| 取消、退换货、退款与保修政策 | 客服、退款权限和状态流转的依据。 |
| 隐私说明、服务条款及联系页面正式文本 | 替换目前待品牌确认的商业内容。 |
| 是否销售自动续费会员订阅 | 自动续费需要单独的订阅方案、取消与续费失败处理，不与单次硬件付款混为同一种接口。 |

上述配置不会因为买家来自欧美、日本或韩国，就自动产生当地货币价格。是否启用 USD、EUR、JPY、KRW、TWD 等币种，应在渠道能力与品牌定价确定后分别配置；绿界的新台币扣款方案应明确提示实际扣款币种。

## 五、开通后交给开发配置的信息

### 所有渠道共用

- [ ] 已获批的商户身份/编号及实际可用支付产品。
- [ ] 测试和正式环境的配置分别准备。
- [ ] API 访问权限、支付结果通知及退款/查询权限。
- [ ] 正式 HTTPS 支付成功、取消和服务器通知地址。
- [ ] 对接技术联系人，以及平台提供的审核或接入说明。
- [ ] 确定由哪些后台管理员负责开通支付、退款及对账。

### 如选择 PayPal

- [ ] 商业账户和关联的开发者应用。
- [ ] 测试及正式环境分别对应的 Client ID、Client Secret。
- [ ] 分环境配置的 Webhook ID 和事件订阅。
- [ ] 用于联调的沙箱商户/买家账户。

应用凭据用于服务器访问 API；Webhook ID 用于通知验证。具体创建步骤由开发协助完成。[PayPal REST 接入](https://developer.paypal.com/api/rest/)、[Webhook 设置与验证](https://developer.paypal.com/api/rest/webhooks/rest/)

### 如选择绿界

- [ ] 已申请且获批的金流产品，以及海外信用卡服务状态。
- [ ] 该产品对应环境的 MerchantID、HashKey、HashIV。
- [ ] 服务端 ReturnURL 和消费者端 OrderResultURL/回跳地址。

不同金流产品的字段与通知规范可能不同；上述字段按其全方位金流接入文档列示，最终以获批产品为准。[测试与正式介接资料](https://developers.ecpay.com.tw/2856/)、[产生订单与回调说明](https://developers.ecpay.com.tw/2862/)

密钥通过部署平台的服务器环境变量配置；不在聊天、前台页面或公开仓库中粘贴。后台只展示是否已配置，不回显完整密钥。

## 六、后续真正接通的验收清单

以下是本项目的工程验收要求：

- [ ] 登录会员可以创建自己的订单，无法读取他人的订单。
- [ ] 订单金额由服务器从已发布商品、数量和有效价格重新计算。
- [ ] 创建付款、重复点击及网络重试不会产生重复付款或重复订单。
- [ ] 支付通知经过渠道规定的验证；校验商户、交易编号、金额与币种。
- [ ] 用户关掉页面或未回到网站，服务器仍能根据有效通知/查询更新付款结果。
- [ ] 浏览器跳到成功地址、或未经验证的通知，不会单独导致“已付款”。
- [ ] 失败、取消、过期、延迟和重复通知有明确处理。
- [ ] 全额/部分退款、异常付款及对账按最终开通功能验收。
- [ ] 管理员、编辑、运营的查看/修改权限与审计记录分别验证。
- [ ] 测试环境全部通过，再由品牌方安排获准的正式验收；本轮不会创建真实交易。

## 七、推荐准备顺序

1. 品牌方确认收款公司、联系人和第一批售卖商品。
2. 与候选支付渠道确认商户资格、币种、跨境能力及审核资料。
3. 完善正式域名、销售资料、配送和退款政策。
4. 商户审核通过后，配置沙箱并完成技术联调。
5. 配置正式凭据，核对币种、金额、通知、退款及权限，再启用收款。

目前不必把资料全部提供给开发；本次后台建设可以先使用独立的支付适配接口和未开通状态，之后依此清单逐项接通。
