# LumiQ 独立官网管理后台设计

日期：2026-10-20。状态：方案范围已确认，本文待用户审阅；尚未开始产品开发或配置云端资源。

代码参考：`huangshaotai737-collab/lumiqwebsite` 的 `main`，提交 `351334d1d5b4f1e69f52af649625a27cf2f5996b`。

## 1. 已确认的目标

为网站负责人和品牌方建立一个可多人协作的管理后台，能够管理官网内容、素材、会员、候补名单和订单。后台修改经过保存、预览和发布后，才反映到官网；日常内容维护不必再修改网页代码。

用户已选择独立后台项目，保留完整功能范围；员工分为管理员、内容编辑和运营三类。公司收款主体在台湾，销售市场为欧美、日本、韩国及台湾。本次支付仅预留接口，并交付后续接通所需材料清单，不开通真实收款。

保留现有官网的电脑和手机布局、动效、产品外形、五款产品和多语言路由。新增会员及订单功能需要接入官网，但不重做现有页面的视觉设计。

**本文采用的默认安排：**独立项目先放在现有 GitHub 仓库的 `related/admin/`，拥有自己的依赖锁文件、启动命令、构建和部署配置。独立项目不等于必须新建另一个仓库。后台界面使用简体中文；官网继续使用现有英文、繁体中文和日文。韩国是销售市场，本次不增加完整韩文翻译。

## 2. 项目与数据如何连接

| 部分 | 职责 | 与其他部分的边界 |
| --- | --- | --- |
| 现有官网 `related/website/` | 展示已发布内容；提供顾客注册登录、个人资料、购物车和订单入口 | 不加载后台样式；不直接读取草稿或员工数据 |
| 独立后台 `related/admin/` | 员工登录；内容、素材、客户和订单管理；发布及操作记录 | 可单独启动和部署；不作为官网每次访问必须调用的服务器 |
| 共用 Supabase 项目 | 数据库、身份认证、素材存储、访问权限 | 前后台通过各自服务器和受权限约束的接口访问同一数据源 |

采用两个独立 Next.js 应用，共用数据库契约。官网读取数据库中的已发布快照，而不是跨站调用后台网页。因此后台服务暂时不可用时，官网仍可读取已发布内容；共享数据库故障仍需按第 11 节降级。

两站使用同一身份服务，但登录 Cookie 按各自域名保存，不通过 URL 传递登录令牌，也不假定跨域自动登录。员工可用同一个账号分别登录官网预览和后台；顾客账号没有后台权限。

数据库迁移统一归档到仓库根目录 `supabase/migrations/`，作为唯一迁移来源。现有候补名单迁移保留原时间戳和内容，迁移位置调整前核对云端迁移记录；不得重新建表覆盖已有报名。两个应用按同一数据库结构生成类型，持续集成检查类型和接口兼容性。

目前只确认仓库已有 Supabase 接入代码，**尚未验证任何现用云端项目、环境变量或真实报名数据**。实施时先核对现有资源；不直接创建付费项目，不假定旧部署账户就是本次部署目标。

## 3. 后台界面与功能

后台采用固定侧栏、顶部操作区和内容工作区。常用列表提供搜索、筛选、分页、空状态和明确的保存反馈；编辑使用表单或侧边详情，避免把大量字段挤入表格。手机后台侧栏折叠，详情纵向排列。

| 导航 | 第一版可操作的内容 |
| --- | --- |
| 工作台 | 实际会员、报名、订单数量；待处理事项、草稿和最近操作。支付未开通时不展示虚构营收 |
| 官网内容 | 页面及模块文案、按钮、产品介绍、常见问题、法律文本、联系方式、SEO 标题和描述 |
| 产品与方案 | 五款产品的展示内容、图片、规格、参考价格；经管理员确认的可下单 SKU 与实际计价设置；方案展示内容 |
| 素材库 | 上传、搜索、预览、替换和查看引用；区分草稿素材与已公开素材 |
| 会员 | 注册会员列表、个人资料、关联订单和运营备注；按权限限制个人信息 |
| 候补名单 | 报名列表、来源、同意版本、处理状态、内部备注、筛选及 CSV 导出 |
| 订单 | 订单详情、明细、金额、币种、客户、状态和处理记录；顾客取消及运营跟进 |
| 团队与权限 | 管理员邀请员工、分配角色、停用员工、查看操作记录 |
| 系统设置 | 官网地址、客服信息、接入配置状态和支付材料清单；不显示完整密钥 |

不加入未提出的拖拽页面搭建器、群发营销系统、设备远程控制或财务会计系统。首页复杂视差、轮播、视频时序和响应式规则仍由代码维护；后台管理这些模块支持的内容字段，不能任意输入脚本或改变布局算法。

## 4. 内容从编辑到发布

1. 首次导入现有网站内容和素材引用，形成与当前官网一致的初始版本。旧素材继续使用现有路径，避免重复上传大量视频。
2. 编辑选择页面和语言，修改结构化字段并保存草稿。字段有长度、类型、链接和素材格式限制，页面明确提示受影响的位置。
3. 后台可打开官网预览指定草稿版本。预览需要有效员工身份，页面显示“草稿预览”；响应不缓存，不被搜索引擎收录。
4. 管理员核对语言、产品引用及素材后发布。编辑可以提交待发布，不自行发布。
5. 发布事务同时保存不可变快照、切换当前版本并记录操作者。网站按版本读取内容，避免一个页面混用新旧字段。
6. 管理员可选择历史版本回滚，回滚生成新的发布记录；不删除历史版本，也不回滚会员、报名或订单。

发布及回滚以数据库事务为准。官网已发布内容缓存最长 60 秒；后台显示生效提示和当前版本号，不承诺所有用户瞬间更新。草稿与会员、订单接口始终 `no-store`。保存草稿使用版本号校验，发生多人编辑冲突时要求重新载入或保留副本，不静默覆盖。

内容范围包括首页各章节、五款产品详情、产品总览、品牌及关于页面、方案展示、候补名单、会员公共介绍、FAQ 和现有法律页面。按钮及重复文案采用共享字段，避免同一行为又出现“登记兴趣”等不同称呼。后台不修改订单邮件或认证邮件里的安全链接生成逻辑。

现有三种语言均可独立编辑。首版从当前文案导入，因此缺翻译不应造成既有语言内容丢失；后续新增必填字段需补齐三语后才能发布，不自动机器翻译。路由、产品 ID 和历史链接保持稳定。`nest` 继续对应展示名称 Lumiq Orb。

方案的年/月价格和权益先作为展示内容管理；本次不实现自动续费、按月扣款或付费会员权益自动发放。

## 5. 素材处理

新素材先进入私有草稿存储，短时授权预览。发布时复制为不可变的公开资源并保存尺寸、类型、大小、替代文本和引用位置；不覆盖已经被发布版本引用的文件。

上传入口校验实际文件类型、扩展名和大小。第一版接受 JPEG、PNG、WebP 图片以及 MP4、WebM 视频，不接受 HTML 或可执行内容；新图片单文件默认上限 20 MB，视频 50 MB，实际可传上限取应用限制与存储服务配置中的较小值，并在界面提示。大文件通过受权限约束的直传上传，不经过普通网页请求体转发。复杂透明视频和背景视频替换前提示其比例及用途要求，不擅自裁切改变人物或产品外形。

已发布或被历史版本引用的素材不能直接永久删除。后台支持归档和查看引用，保证历史版本可回滚。顾客私人数据与公开官网素材不共用公开存储桶。本次会员使用默认头像，不提供任意文件上传。

## 6. 真实会员与官网联动

- 使用 Supabase Auth 实现邮箱注册、验证、登录、退出和密码重置；官网服务器验证身份，不能仅凭浏览器本地标志判断已登录。
- 注册后可维护本人姓名、显示语言和收件资料，并查看自己的订单。购买前后都不向普通会员开放其他客户信息。
- 管理员和运营可查客户服务所需信息及内部备注；内容编辑无法查看会员、订单或报名邮箱。内部备注不会返回顾客端。
- 现有本地会员演示资料不自动视为真实账号、真实设备或已购权益。设备控制、设备绑定与云端同步仍需设备服务接口，本次不做成假的可控设备。
- 现有本地购物车继续允许访客浏览和加购；创建持久订单需要登录。会员资料、收件地址和订单只通过服务器验证后的接口访问。

邮箱发送需要正式 SMTP、发信域名和认证跳转白名单。开发可先使用本地邮件捕获器验证流程；未配置正式邮件、数据库和域名时，只能交付本地或测试环境，不能宣称品牌用户已经能在生产环境注册。

## 7. 订单与支付预留边界

### 7.1 没有支付渠道时如何使用

本次提供真实持久化的订单结构与流程，但公开购买开关初始关闭。品牌确认产品、价格、交付及取消规则后，管理员才能启用“提交待开放订单”；顾客提交前会看到“支付尚未开放，提交不会扣款，也不代表已确认购买”。

服务器只接受管理员已确认且允许提交的 SKU，重新计算金额并生成订单。订单初始为 `pending_payment_setup`，顾客可取消，运营可查看与备注。未确认价格的产品、随 OLA 提供的 Go 配件不能被当作独立收费商品。初始目录中的 USD 599、399、69 是参考信息，不自动开启销售。

第一版不承诺实时库存、不扣减库存、不产生付款成功或发货操作。公开提交开关未打开时，官网继续引导加入候补名单；在本地/测试环境可用测试 SKU 验证订单完整流程。

### 7.2 金额与状态规则

- 订单保存商品名称、SKU、数量、单价、币种和商业条款版本的快照；后续改产品文案或价格不改历史订单。
- 金额采用币种最小单位整数，单笔订单只包含一种币种。实际扣款币种独立于语言和访客所在地；不按国家自动换汇。
- 订单业务状态、付款状态和配送状态分别存储。本轮业务状态为待支付开放/已取消，付款状态为未开通，配送状态为未安排。
- 创建订单使用“会员 + 幂等键”和事务，防止重复点击、重试生成多单；取消同样幂等。备注不能改变支付或配送状态。
- 未来的待付款、已付款、失败、退款和配送状态属于支付/履约接入后的扩展，当前不向后台开放伪造已付款的按钮。

### 7.3 支付适配接口

预留创建结账、查询交易、核验并处理通知、申请退款及查询退款结果的服务端契约，同时记录支付尝试、服务商交易号、事件去重键和错误类别。

未配置渠道统一返回 `PAYMENTS_NOT_CONFIGURED`。生产环境没有可返回“支付成功”的模拟渠道；测试替身只在自动化测试中使用。未来渠道适配器必须核验商户、订单、金额、币种及通知真实性，使用幂等状态转换；浏览器成功页和未经验证的通知都不能把订单改为已付款。接口预留不代表已完成渠道签名验证、退款、订阅或对账接入。

台湾主体的候选渠道和开户、商户审核、定价、配送、凭据及后续验收资料详见 [支付接通准备清单](./2026-10-20-lumiq-payments-readiness.md)。本次不创建真实交易，不启用付费订阅，不申请商户账户。

## 8. 员工权限与操作记录

| 操作 | 管理员 | 内容编辑 | 运营 |
| --- | --- | --- | --- |
| 内容与素材草稿、预览 | 允许 | 允许 | 仅查看已发布内容 |
| 发布、回滚 | 允许 | 提交待发布 | 不允许 |
| SKU 实际价格、提交开关 | 允许 | 仅编辑展示介绍 | 仅查看 |
| 会员、报名、订单及运营备注 | 允许 | 不允许 | 允许 |
| 报名 CSV 导出 | 允许 | 不允许 | 允许，记录导出范围 |
| 员工邀请、角色、停用、系统配置 | 允许 | 不允许 | 不允许 |
| 查看完整操作日志 | 允许 | 仅本人内容操作 | 仅本人运营操作 |
| 修改付款为成功、发起真实退款、标记发货 | 本次均不开放 | 本次均不开放 | 本次均不开放 |

员工通过管理员邀请获得权限，公开注册不会自动成为员工。第一位管理员由服务器一次性引导流程创建，需指定收件邮箱；公开应用不提供初始化管理员的入口，仓库不保存默认管理员密码。禁止停用或降级最后一位管理员。

角色以数据库中的在职状态为准，每次敏感操作重新校验，不信任浏览器提交的角色、可自行修改的用户资料或仅依赖旧令牌中的角色。停用后下一次后台请求应被拒绝；普通会员登录仍不产生员工权限。

发布、回滚、角色变更、报名导出和订单状态/备注操作记录操作者、时间、对象、动作和必要的变更摘要。关键数据库变更与日志同一事务提交。日志不允许从后台修改或删除，不存密码、令牌、完整身份材料或多余的客户个人信息。运营没有单独删除整个会员或所有订单的权限；需要删除客户资料时由管理员执行受审计的匿名化流程，并按实际业务确认保留范围。

## 9. 数据与接口契约

| 数据组 | 核心记录与约束 |
| --- | --- |
| 身份与权限 | `profiles`、`staff_memberships`、员工邀请；用户身份使用认证用户 ID，后台角色不写入用户自改字段 |
| 内容 | `content_drafts`、`content_releases`、当前版本指针；版本、语言、模块 ID、结构版本及发布记录 |
| 素材 | `media_assets`、`media_references`；草稿/公开状态、不可变路径、类型及引用 |
| 产品 | 稳定产品 ID、展示字段；独立 SKU、经确认的币种价格、是否可提交 |
| 客户运营 | 原有 `waitlist_signups`；分离的处理状态/备注；会员内部备注 |
| 订单 | `orders`、`order_items`、状态事件、创建幂等键；会员归属、金额与条款快照 |
| 支付预留 | `payment_attempts`、通知事件去重记录、退款记录；初始没有真实渠道凭据或成功交易 |
| 审计 | 追加式 `audit_events`；必要对象引用与动作摘要 |

公开内容只返回当前已发布快照。会员接口只允许访问本人资料及订单；员工接口按上表授权。订单创建与发布通过受保护的事务函数执行，前端不能直接写订单金额或切换发布指针。

数据库对私有表启用 RLS，并逐项配置表级授权；认证身份本身不等于有权读取整张表。辅助数据库函数限制可执行角色并固定 `search_path`；必须使用提权函数时在函数内部重复验证调用者和对象范围。

大多数日常读写使用当前用户令牌和 RLS。高权限服务器密钥仅用于已验证管理员的员工邀请、初始化等确有需要的服务器操作；现有报名插入接口可以继续采用服务器专用凭据。浏览器、公开接口响应及日志不得包含这些凭据。

本次不暴露通用数据库查询、任意 SQL、任意文件路径或任意 URL 抓取接口。两个应用的接口都校验输入、认证及来源；基于 Cookie 的写请求验证 Origin/CSRF。登录、报名、订单提交和导出配置跨实例有效的限流，不能只靠单进程内存计数。

## 10. 官网接入与迁移

首先以最新主分支建立桌面/手机基线，导入当前内容为初始发布快照。保持原组件结构和样式，通过内容适配层替换字符串、目录和素材来源；不把整个首页重构成新的渲染器。

所有内容均读取完整、已校验的发布版本；没有任何发布记录时使用随代码带入的初始快照。遇到数据库故障，优先读取最近已成功缓存的发布快照，否则回退初始快照并记录告警；不把失败的空数据覆盖为已发布内容。

涉及交易的实际价格、可提交资格与权限不使用离线内容回退。无法核验时关闭提交、提示稍后重试，不用缓存参考价创建订单。会员、订单、候补名单保存失败时明确提示失败，不显示保存成功。

原有候补名单接口保持邮箱去重与同意版本，增加后台读取权限时不开放匿名读取。现有报名是否实际存储，需要以真实环境中的插入、去重和后台读取验证，不能以构建成功替代。

公共展示缓存与私有数据请求分离。会员/后台页面不可进入共享静态缓存；新认证会话刷新流程与现有多语言中间件组合验证，不影响现有语言跳转、SEO 或公开页面访问。

## 11. 错误与恢复

保存失败保留未提交输入，给出可重试信息；登录过期先重新认证，不自动重放付款或发布等敏感请求。无权限返回明确拒绝，不用隐藏菜单代替后端授权。

发布事务失败维持旧版本；发布成功但部分访问仍使用缓存时提示最长 60 秒的传播时间。素材未完成上传或格式不匹配时阻止发布并定位字段。

订单创建结果不明确时按原幂等键查询并重试，不能无条件新建。后台工作台读取失败显示不可用，不以 0 或虚构示例代替真实统计。

数据库迁移先在独立测试环境验证备份与恢复流程，采取可向后兼容的字段扩展；发布应用前核对迁移版本。回滚后台部署不能撤销已经发生的业务数据。生产数据备份与保留策略根据最终选用的托管套餐明确配置，未配置时列为上线阻断项。

## 13. 交付顺序与上线依赖

实施按相互衔接的五个增量进行：独立项目及认证权限 → 内容素材与官网发布 → 真实会员及报名运营 → 订单与支付契约 → 前后台完整走查、交接和部署说明。每个增量有相应验收，全部通过后才宣称本次功能范围完成。

代码交付包含两个独立应用、单一数据库迁移历史、无密钥环境变量示例、初始化管理员流程、测试、部署/回退说明、后台使用说明及支付材料清单。开发分支与原官网版本可追溯；不因本文确认就自动推送主分支、上线生产或开通付款。

生产接入时需要：品牌方确认的 Supabase 项目/托管归属、官网与后台 HTTPS 地址、第一位管理员邮箱、发信服务及域名、客户资料保留要求，以及测试/生产环境分别配置。若暂未提供，可完成本地和测试实现，生产启用步骤保持明确待配置状态；不需要品牌方现在把证件或密钥发到聊天里。

支付渠道的正式审核和凭据不阻塞本次预留接口的代码交付；正式会员邮件、生产数据存储、备份与访问权限未验证，则阻止宣称生产后台已可用。
